JavaScript

Rendre une page web interactive : variables, fonctions, DOM, événements, asynchrone — niveau BTS CIEL, avec des repères pour ceux qui viennent de Python.

À RETENIR
JavaScript est le langage qui s'exécute dans le navigateur (contrairement à Python côté serveur) : il donne vie à une page HTML/CSS statique en réagissant aux actions de l'utilisateur (clics, saisies) et en modifiant la page sans la recharger.
🐍 SI TU VIENS DE PYTHON
Tu connais déjà les concepts (variables, fonctions, boucles, POO, appels d'API) : ce cours va surtout t'apprendre une nouvelle syntaxe et quelques mécanismes propres à JS qui n'existent pas en Python (le DOM, l'asynchrone omniprésent, this). Des encadrés bleus 🐍 feront le pont avec Python tout au long du cours.

1. Introduction : à quoi sert JavaScript et où l'écrire

HTML structure une page, CSS l'habille, JavaScript la rend interactive : réagir à un clic, valider un formulaire avant envoi, charger des données sans recharger la page, animer des éléments... C'est le seul langage compris nativement par tous les navigateurs.

<script>
  console.log("Bonjour depuis JavaScript !");
</script>

<script src="script.js" defer></script> // fichier externe, méthode recommandée
À RETENIR
console.log(...) est ton meilleur ami pour débuter : il affiche une valeur dans la console du navigateur (touche F12 puis onglet "Console"), sans interrompre la page comme le ferait une alerte. Prends l'habitude de l'ouvrir en permanence pendant que tu codes.
🐍 SI TU VIENS DE PYTHON
console.log() ≈ print(). La grande différence : ton code Python s'exécute dans un terminal, ton code JS s'exécute dans le navigateur, avec accès à la page (le DOM) que Python n'a pas.

2. Variables et types

let age = 17;              // variable qui peut changer de valeur
const nom = "Amir";        // constante : ne peut plus être réaffectée
var ancien = "à éviter";   // ancienne syntaxe, portée différente (voir attention)
Mot-cléUsage
letVariable modifiable — à utiliser par défaut
constValeur qui ne sera jamais réassignée — à préférer dès que possible, pour la lisibilité
varAncienne syntaxe (avant 2015), à éviter : sa portée fonctionne différemment et cause des bugs (voir encadré ci-dessous)
TypeExemple
Nombre (un seul type, pas de distinction int/float)let n = 42; let pi = 3.14;
Chaîne de caractèreslet s = "bonjour"; let s2 = 'aussi valide';
Booléenlet actif = true;
Tableaulet notes = [12, 15, 8];
Objetlet personne = { nom: "Amir", age: 17 };
undefinedUne variable déclarée mais jamais initialisée
nullUne absence de valeur, définie volontairement par le développeur
ATTENTION — piège classique : var vs let
var a une portée de fonction, alors que let/const ont une portée de bloc (comme en Python, une variable dans un if ou un for avec let n'existe pas en dehors). Avec var, une variable déclarée dans un if "fuit" en dehors du bloc — source de bugs très courante chez les débutants. Solution : n'utilisez jamais var. 
if (true) {
  let x = 10;
  var y = 20;
}
console.log(y); // -> 20, fonctionne (surprenant !)
console.log(x); // -> Erreur : x is not defined
ATTENTION — undefined vs null
undefined = "cette variable n'a jamais reçu de valeur" (souvent un oubli/bug). null = "j'ai volontairement dit qu'il n'y a pas de valeur ici". En Python, il n'existe qu'un seul concept (None) qui correspond aux deux à la fois — c'est une vraie différence à intégrer.
🐍 SI TU VIENS DE PYTHON
Pas de distinction int/float en JS : tout nombre est du type number. Les chaînes se déclarent avec "..." ou '...', indifféremment (contrairement à Python où c'est aussi le cas, donc rien de neuf ici). Chaque instruction se termine par un point-virgule ; (facultatif techniquement, mais fortement recommandé).

3. Opérateurs et structures de contrôle

if (note >= 10) {
  console.log("Admis");
} else if (note >= 8) {
  console.log("Rattrapage");
} else {
  console.log("Recalé");
}

for (let i = 0; i < 5; i++) {
  console.log(i);
}

let notes = [12, 15, 8];
for (const n of notes) {       // parcourt les VALEURS d'un tableau
  console.log(n);
}

let i = 0;
while (i < 3) {
  console.log(i);
  i++;
}
OpérateurSignification
==Égalité avec conversion de type automatique — à éviter
===Égalité stricte, sans conversion — à utiliser systématiquement
&& / || / !ET / OU / NON logiques
+=, -=, ++, --Affectations et incrémentations composées, comme en Python (sauf ++ / -- qui n'existent pas en Python)
ATTENTION — le piège n°1 de JavaScript : == vs ===
"5" == 5 vaut true (JS convertit la chaîne en nombre avant de comparer), alors que "5" === 5 vaut false (types différents, donc jamais égaux). Cette conversion automatique de == produit des résultats surprenants (0 == false est true, "" == false aussi). Prenez l'habitude d'utiliser === et !== partout, sans exception.

4. Fonctions

// déclaration classique
function addition(a, b) {
  return a + b;
}

// expression de fonction
const soustraction = function(a, b) {
  return a - b;
};

// fonction fléchée (arrow function) — syntaxe moderne, très utilisée
const multiplication = (a, b) => {
  return a * b;
};

// fonction fléchée courte : une seule expression, retour implicite
const carre = x => x * x;

addition(3, 4);       // -> 7
carre(5);              // -> 25
SyntaxeQuand l'utiliser
Déclaration function nom() {}Fonctions "utilitaires" classiques, hissées en haut du fichier (voir hoisting, section 10)
Fléchée const f = () => {}Très utilisée pour des fonctions courtes, callbacks, et dans les méthodes de tableau (section 5)
🐍 SI TU VIENS DE PYTHON
const carre = x => x * x; ressemble à une lambda Python (carre = lambda x: x*x), mais en JS les fonctions fléchées sont utilisées partout, pas seulement pour des cas courts — elles remplacent souvent function classique.
ATTENTION
Une fonction déclarée avec function peut être appelée avant sa définition dans le fichier (hoisting). Une fonction fléchée stockée dans une const ne le peut pas — elle doit être définie avant d'être utilisée, comme en Python.

5. Tableaux (Array) et leurs méthodes

let notes = [12, 15, 8, 17];

notes.push(10);            // ajoute à la fin -> [12, 15, 8, 17, 10]
notes.length;               // -> 5
notes[0];                   // -> 12 (indexation à partir de 0, comme Python)

// forEach : exécute une fonction pour chaque élément (pas de retour)
notes.forEach(n => console.log(n));

// map : transforme chaque élément, renvoie un NOUVEAU tableau
const doublees = notes.map(n => n * 2);

// filter : garde seulement les éléments qui vérifient une condition
const bonnes = notes.filter(n => n >= 10);

// find : renvoie le PREMIER élément qui vérifie une condition (ou undefined)
const premiereMauvaise = notes.find(n => n < 10);

// reduce : accumule les éléments en une seule valeur
const somme = notes.reduce((acc, n) => acc + n, 0);
MéthodeÉquivalent Python approximatif
mapList comprehension [f(x) for x in liste]
filter[x for x in liste if condition]
reducefunctools.reduce
forEachfor x in liste: ... (sans valeur de retour)
À RETENIR
map et filter renvoient toujours un nouveau tableau, sans modifier l'original — un réflexe à prendre pour éviter des effets de bord inattendus.

6. Objets

const etudiant = {
  nom: "Amir",
  age: 17,
  matieres: ["Maths", "NSI"],
  seFesenter() {                 // méthode : fonction dans un objet
    return `Je m'appelle ${this.nom} et j'ai ${this.age} ans.`;
  }
};

etudiant.nom;                 // -> "Amir" (accès par point)
etudiant["age"];              // -> 17 (accès par crochets, utile si clé dynamique)
etudiant.ville = "Paris";     // ajoute une nouvelle propriété
etudiant.seFesenter();        // -> "Je m'appelle Amir et j'ai 17 ans."

for (const cle in etudiant) {  // parcourt les CLÉS d'un objet
  console.log(cle, etudiant[cle]);
}
🐍 SI TU VIENS DE PYTHON
Un objet JS ressemble beaucoup à un dictionnaire Python ({"nom": "Amir", "age": 17}), avec en plus la possibilité d'y mettre des méthodes directement, façon mini-classe. for...in sur un objet ≈ for cle in dictionnaire:, alors que for...of sur un tableau ≈ for element in liste: — ne confondez pas les deux (section 3 et 5).
ATTENTION — this dans une méthode
À l'intérieur d'une méthode d'objet, this désigne l'objet lui-même — un peu comme self en Python, mais this est implicite (jamais un paramètre explicite de la fonction). Ce comportement se complique avec les fonctions fléchées (voir section 11, hors programme).

7. Le DOM : lire et modifier la page

Le DOM (Document Object Model) est la représentation de la page HTML sous forme d'objets manipulables en JavaScript.

const titre = document.querySelector("h1");        // premier élément correspondant
const tousLesP = document.querySelectorAll("p");    // TOUS les éléments correspondants (liste)
const parId = document.getElementById("mon-id");

titre.textContent = "Nouveau titre";     // change le texte (sûr)
titre.innerHTML = "<em>Titre</em>";     // change le HTML interne (attention aux failles XSS avec du contenu utilisateur)
titre.style.color = "red";               // modifie un style CSS directement
titre.classList.add("actif");            // ajoute une classe CSS

const nouveauP = document.createElement("p");
nouveauP.textContent = "Élément créé dynamiquement";
document.body.appendChild(nouveauP);      // l'ajoute réellement à la page
MéthodeRôle
querySelector(sel)Renvoie le premier élément qui correspond au sélecteur CSS sel
querySelectorAll(sel)Renvoie TOUS les éléments correspondants
textContentLit ou change le texte affiché
createElement + appendChildCrée un nouvel élément puis l'insère dans la page
À RETENIR
Le sélecteur passé à querySelector est un sélecteur CSS classique : "#mon-id", ".ma-classe", "div p"... Si tu connais les sélecteurs CSS, tu sais déjà cibler des éléments en JS.

8. Les événements

const bouton = document.querySelector("#mon-bouton");

bouton.addEventListener("click", function() {
  console.log("Cliqué !");
});

// avec une fonction fléchée, souvent plus court
bouton.addEventListener("click", () => {
  console.log("Cliqué aussi !");
});

// l'objet "event" donne des infos sur l'événement
document.querySelector("form").addEventListener("submit", (event) => {
  event.preventDefault();  // empêche le rechargement de page par défaut
  console.log("Formulaire intercepté avant envoi");
});
ÉvénementSe déclenche quand...
clickL'utilisateur clique sur l'élément
inputLa valeur d'un champ change (à chaque frappe)
submitUn formulaire est envoyé
keydown / keyupUne touche du clavier est pressée / relâchée
DOMContentLoadedLa page HTML a fini de se charger (sur document)
ATTENTION
event.preventDefault() est indispensable pour intercepter un formulaire côté JS sans que le navigateur ne recharge immédiatement la page (comportement par défaut d'un submit).

9. L'asynchrone : Promises, async/await, fetch

Beaucoup d'opérations en JS prennent du temps (charger une image, interroger un serveur) sans bloquer le reste de la page pendant l'attente — c'est le principe de l'asynchrone, omniprésent en JS.

// fetch renvoie une PROMISE (une valeur "pas encore prête")
fetch("https://jsonplaceholder.typicode.com/users/1")
  .then(reponse => reponse.json())   // convertit la réponse en objet JS
  .then(donnees => console.log(donnees))
  .catch(erreur => console.error("Erreur :", erreur));

// même chose avec async/await, plus lisible (syntaxe recommandée)
async function chargerUtilisateur() {
  try {
    const reponse = await fetch("https://jsonplaceholder.typicode.com/users/1");
    const donnees = await reponse.json();
    console.log(donnees);
  } catch (erreur) {
    console.error("Erreur :", erreur);
  }
}
chargerUtilisateur();
ConceptExplication
PromiseObjet représentant une valeur qui sera disponible plus tard (succès ou échec)
.then()Exécuté quand la Promise réussit
.catch()Exécuté si la Promise échoue (erreur réseau, etc.)
asyncMarque une fonction comme pouvant utiliser await à l'intérieur
await"Attend" qu'une Promise se résolve avant de continuer, comme un appel classique
🐍 SI TU VIENS DE PYTHON
async/await existe aussi en Python (async def, await) avec exactement la même logique. Si tu as fait des appels d'API en Python avec requests (synchrone) : fetch + await en JS te donne un résultat équivalent, mais l'asynchrone est la norme en JS (pas une option comme en Python), car JavaScript est mono-thread et ne doit jamais bloquer l'interface.
ATTENTION — piège classique
await ne peut être utilisé qu'à l'intérieur d'une fonction marquée async. Oublier async devant la fonction est une erreur très fréquente chez les débutants (le code refuse de compiler avec un message peu clair au premier abord).

10. Closures et portée lexicale + hors programme

Une closure (fermeture) est une fonction qui "se souvient" des variables de l'endroit où elle a été créée, même après que cet endroit a fini de s'exécuter.

function creerCompteur() {
  let compte = 0;
  return function() {
    compte++;
    return compte;
  };
}

const compteur = creerCompteur();
compteur(); // -> 1
compteur(); // -> 2
compteur(); // -> 3
À RETENIR
La variable compte devrait normalement disparaître à la fin de l'exécution de creerCompteur() — mais la fonction retournée la "garde en mémoire" grâce à la closure. C'est le mécanisme derrière beaucoup de patterns JS avancés (compteurs, gestionnaires d'état, fonctions "fabriques").

11. this en profondeur + hors programme

La valeur de this dépend de comment une fonction est appelée, pas de où elle est écrite :

const objet = {
  nom: "Amir",
  direBonjour: function() {
    console.log(this.nom); // -> "Amir" : this = objet, car appelée via objet.direBonjour()
  },
  direBonjourFleche: () => {
    console.log(this.nom); // -> undefined : les fonctions fléchées n'ont PAS leur propre this
  }
};
objet.direBonjour();
objet.direBonjourFleche();

Pour forcer la valeur de this dans un cas précis : fonction.call(contexte), fonction.apply(contexte, args), ou fonction.bind(contexte) (renvoie une nouvelle fonction liée définitivement à ce contexte).

ATTENTION
Les fonctions fléchées n'ont pas leur propre this : elles récupèrent celui du contexte englobant au moment où elles sont écrites (portée lexicale). C'est très utile dans un callback (pour garder le this de la méthode englobante), mais problématique si on les utilise comme méthode directe d'un objet.

12. Programmation orientée objet en JavaScript + hors programme

class Etudiant {
  constructor(nom, age) {
    this.nom = nom;
    this.age = age;
  }
  seFesenter() {
    return `Je m'appelle ${this.nom}, j'ai ${this.age} ans.`;
  }
}

class EtudiantBTS extends Etudiant {
  constructor(nom, age, specialite) {
    super(nom, age);            // appelle le constructeur parent
    this.specialite = specialite;
  }
  seFesenter() {
    return super.seFesenter() + ` Spécialité : ${this.specialite}.`;
  }
}

const e = new EtudiantBTS("Amir", 17, "CIEL");
console.log(e.seFesenter());
🐍 SI TU VIENS DE PYTHON
constructor ≈ __init__. this ≈ self, mais implicite (pas un paramètre explicite de chaque méthode). extends ≈ hériter entre parenthèses (class EtudiantBTS(Etudiant):). super() fonctionne quasiment pareil dans les deux langages.

13. Consommer une API JSON en pratique + hors programme

async function afficherUtilisateurs() {
  const reponse = await fetch("https://jsonplaceholder.typicode.com/users");
  const utilisateurs = await reponse.json();

  const conteneur = document.querySelector("#liste-utilisateurs");
  utilisateurs.forEach(u => {
    const li = document.createElement("li");
    li.textContent = `${u.name} (${u.email})`;
    conteneur.appendChild(li);
  });
}

Ce pattern — fetch + await + parcours avec forEach + création d'éléments DOM — est l'un des plus courants du développement web front-end : récupérer des données d'une API et les afficher dynamiquement dans la page.
